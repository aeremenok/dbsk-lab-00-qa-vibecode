# Каталог багов

В `src/discount.ts` намеренно заложено пять багов. Все они нарушают правила, описанные в `README.md` (раздел бизнес-логики). Каждый баг сопровождён минимальным тестом-ловушкой в `tests/discount.test.ts`.

---

## Баг 1 — потолок скидки не применяется

- **Нарушенное правило:** №2 — потолок скидки 1000 копеек (10 ₽).
- **Текущая строка:**
  ```ts
  percentDiscount = total * 0.1;
  ```
- **Корректно:**
  ```ts
  percentDiscount = Math.min(Math.round(total * 0.1), 1000);
  ```
- **Почему AI обычно пропускает.** Типичный happy-path-тест для процентной скидки берёт круглый total (например, 10 000 копеек), где 10% и так равны потолку — баг не виден. Чтобы поймать, нужен сценарий «сильно выше порога», который AI редко отдельно генерирует, если в коде нет явной константы лимита.

---

## Баг 2 — промокод не проверяется на срок действия

- **Нарушенное правило:** №6 — просроченный промокод (`expiresAt < now`) игнорируется.
- **Текущая строка:**
  ```ts
  if (promo) {
    // ...применяется без проверки expiresAt
  }
  ```
- **Корректно:**
  ```ts
  if (promo && promo.expiresAt >= now) {
    // ...
  }
  ```
- **Почему AI обычно пропускает.** Параметр `now` в сигнатуре есть, но без чтения бизнес-правил его роль не очевидна. AI в большинстве случаев тестирует «промо есть» / «промо нет», но не «промо просрочен». Поле `expiresAt` визуально выглядит как метаданные.

---

## Баг 3 — скидки складываются вместо выбора бóльшей

- **Нарушенное правило:** №5 — промокоды не совмещаются с автоматической процентной скидкой; применяется бóльшая из двух.
- **Текущая строка:**
  ```ts
  const discountAmount = percentDiscount + promoDiscount;
  ```
- **Корректно:**
  ```ts
  const discountAmount = Math.max(percentDiscount, promoDiscount);
  ```
- **Почему AI обычно пропускает.** Чтобы поймать, нужен сценарий, где одновременно применимы и автоматическая скидка (total ≥ 5000), и валидный промокод. AI охотно пишет тесты на каждое правило в изоляции, но на их пересечение — реже, особенно если в коде нет явного `if`-блока «обе скидки применимы».

---

## Баг 4 — заказ с суммой ровно 0 не вызывает ошибку

- **Нарушенное правило:** №8 — сумма заказа ≤ 0 → ошибка.
- **Текущая строка:**
  ```ts
  if (total < 0) {
    throw new Error('Invalid order total');
  }
  ```
- **Корректно:**
  ```ts
  if (total <= 0) {
    throw new Error('Invalid order total');
  }
  ```
- **Почему AI обычно пропускает.** Тесты на отрицательную сумму AI пишет почти всегда, но граничный случай `total === 0` через `price = 0` для непустой корзины — нет. В голову AI приходит только «пустая корзина», а сценарий «корзина с нулевыми ценами» он не моделирует.

---

## Баг 5 — дробные копейки

- **Нарушенное правило:** все суммы в копейках — целые числа (преамбула бизнес-правил).
- **Текущая строка:**
  ```ts
  promoDiscount = total * (promo.value / 100);
  ```
- **Корректно:**
  ```ts
  promoDiscount = Math.round(total * (promo.value / 100));
  ```
  (То же — для `percentDiscount`.)
- **Почему AI обычно пропускает.** AI часто использует `toBeCloseTo` для проверки «примерно правильной» скидки, что маскирует дробные копейки. Проверка `Number.isInteger(discountAmount)` ему в голову не приходит, если в требованиях явно не указано «целое».
