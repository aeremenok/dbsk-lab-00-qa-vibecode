# Зелёные галочки лгут — лабораторная работа

Эксперимент по AI-тестированию. Небольшой TypeScript-сервис расчёта скидок для интернет-магазина — заведомо багованный. Задача: посмотреть, какие тесты сгенерирует AI и сколько багов они реально поймают.

> **Внимание.** Тесты, которые вы напишете (или сгенерируете), **должны падать** — баги в коде заложены намеренно. Зелёные галочки на этом коде означают, что тесты слабые, а не что код корректен.

## Быстрый старт

```bash
git clone <repo-url>
cd dbsk-lab-00-qa-vibecode
npm install
npm test
```

Папка `tests/` пуста — это нормально. Сюда вы кладёте тесты, написанные руками или сгенерированные AI.

## Раунды эксперимента

1. **Ветка `main` (строгие типы).** Просите AI написать unit-тесты для `src/discount.ts` со всеми типами на месте. Запускаете, смотрите, сколько багов реально пойманы.
2. **Ветка `loose` (всё `any`).** Та же логика, но без типов. Просите AI снова сгенерировать тесты. Сравниваете покрытие и качество.
3. **Сравнение с эталоном.** Ветка `solutions` содержит эталонный набор тестов и разбор всех заложенных багов в `solutions/BUGS.md`. Сверяете: какие AI поймал, а какие пропустил.

## Структура

```
src/discount.ts          # сервис со скидками (с багами)
tests/                   # сюда пишутся тесты
prompts/                 # SDD-промпты для AI
solutions/               # только на ветке solutions: эталон + разбор
```
